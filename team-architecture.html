start-feature /start-feature

手动触发 — 开始新功能 / 修 bug 时
一条命令完成：检查工作区 → 拉最新代码 → 建分支 → 建目录 → 生成接口契约模板
STEP 1检查未提交代码
STEP 2确认功能名称
STEP 3拉最新 main
STEP 4建 feature 分支
STEP 5建目录结构
STEP 6生成 CONTRACT.md
🔗

sync-shared /sync-shared

手动触发 — 改了 shared/ 代码时
检测公共代码变更 → 分析影响范围 → 生成变更摘要 → 可复制到 PR 描述或团队群
STEP 1检测 shared/ 变更
STEP 2grep 查找依赖方
STEP 3生成变更摘要
STEP 4通知 / 加入 PR
🔍

pre-push /pre-push

手动触发 — 推送前（核心 Skill）
检查点去重 → AI 审代码细节 → 人审架构决策 → 生成 PR 描述 → 推送 + 创建 PR
STEP 1检查点去重
STEP 2收集 diff 上下文
STEP 3AI 代码审查
STEP 4人审架构
STEP 5生成 PR 描述
STEP 6推送 + 创建 PR
AI 审什么
语法错误、边界条件、安全漏洞、代码风格、幻觉 API、测试覆盖
人审什么
设计模式、业务逻辑、模块耦合、可维护性、性能风险
📚

扫描变更文件 → 更新 API 文档 → 同步 CLAUDE.md → 清理过时文档
STEP 1扫描变更
STEP 2更新 API 文档

STEP 4清理过时文档

using-superpowers 自动加载

自动触发 — 每次会话启动时
定义 Skill 优先级、开发流程规范、团队协作原则。所有其他 Skill 的行为都受它约束

检查点机制（避免重复运行）

# .claude/.skill-checkpoints 文件示例 pre-push|feature/login|2026-05-15T10:30:00|abc1234 neat-freak|feature/login|2026-05-15T09:00:00|def5678 # 格式: skill名|分支名|时间戳|commit hash # 同分支 + 同 commit = 跳过（已跑过） # 新 commit = hash 不匹配 = 自动重新运行
多 Agent 协同
AGENTS.md 是跨工具的单一事实源

Claude Code 配置

在项目的 CLAUDE.md 顶部加一行导入：

# CLAUDE.md @AGENTS.md # 以下是 Claude Code 专属指令... # 架构细节、命令速查、编码原则

Codex 配置

原生读取项目根目录的 AGENTS.md，零配置：

# 不需要任何操作 # Codex 启动时自动读取 AGENTS.md ✓ 开箱即用 ✓ 改 AGENTS.md 两边同时生效

Claude Code 用户必做

在项目的 CLAUDE.md 顶部添加 @AGENTS.md。
不加这一行，Claude Code 不会读取 AGENTS.md 里的团队规则。
Codex 用户不需要任何操作。

AGENTS.md 应该包含什么

# AGENTS.md ## 项目概览 一句话说清楚项目是什么 ## 模块分工 谁负责哪个 feature/目录 ## 协作规范 分支命名、PR 流程、代码风格 ## 红线 AI 绝对不能做的事（如直接推 main） ## 阅读顺序 先读什么、再读什么的指引
