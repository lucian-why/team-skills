团队自定义 Skill 4 个
Skill 触发 做什么 来源
start-feature 手动 每次开发新功能前。检查工作区 → 拉最新代码 → 建 feature 分支 → 建目录结构 → 生成 CONTRACT.md 团队自定义
sync-shared 手动 改了 shared/ 或公共模块后。检测变更 → grep 查找依赖方 → 生成变更摘要 → 通知下游 团队自定义
pre-push 手动 每次推代码前必跑，不能跳过。AI 审代码细节 → 人审架构决策 → 生成 PR 描述 → 推送 + 创建 PR 团队自定义（核心）
neat-freak 手动 功能完成后。扫描变更 → 更新 API 文档 → 同步 CLAUDE.md → 清理过时文档 团队自定义

Skill 触发 做什么 来源
using-superpowers 自动 工作流总纲 — 定义 Skill 优先级、开发流程、协作原则。所有其他 Skill 的行为受它约束 superpowers
brainstorming 手动 把模糊想法变成完整设计 — 逐个提问理清需求，输出设计文档和规格说明 superpowers
writing-plans 手动 把设计拆成可执行的实施计划 — 任务列表、依赖关系、验收标准 superpowers
executing-plans 手动 按计划逐任务执行 — 跟踪进度、处理阻塞、确保每步可验证 superpowers
subagent-driven-development 手动 每个任务派发独立子代理执行 — 隔离上下文，任务间做两轮 review（规格 + 代码质量） superpowers
dispatching-parallel-agents 手动 多个独立任务并行派发 — 同时执行互不依赖的任务，加速开发 superpowers

pre-push 详解（核心 Skill）

STEP 1
检查点去重
STEP 2
收集 diff
STEP 3
AI 审代码
STEP 4
人审架构
STEP 5
生成 PR 描述
STEP 6
推送 + 建 PR
AI 审什么
语法错误、边界条件、安全漏洞、代码风格、幻觉 API、测试覆盖、依赖合理性
人审什么
设计模式、业务逻辑、模块耦合、可维护性、性能风险。不懂代码也能审——审的是"这样做对不对"

检查点机制（避免重复运行）

# .claude/.skill-checkpoints pre-push|feature/login|2026-05-15T10:30:00|abc1234 # 同分支 + 同 commit = 跳过 # 新 commit = hash 不匹配 = 自动重新运行
多 Agent 协同
AGENTS.md 是跨工具的单一事实源

Claude Code 配置

在项目的 CLAUDE.md 顶部加一行导入：

# CLAUDE.md @AGENTS.md # 以下是 Claude Code 专属指令...

Codex 配置

原生读取项目根目录的 AGENTS.md，零配置：

# 不需要任何操作 ✓ 开箱即用 ✓ 改 AGENTS.md 两边同时生效

Claude Code 用户必做

在项目的 CLAUDE.md 顶部添加 @AGENTS.md。
不加这一行，Claude Code 不会读取 AGENTS.md 里的团队规则。
Codex 用户不需要任何操作。

AGENTS.md 应该包含什么

# AGENTS.md ## 项目概览 一句话说清楚项目是什么 ## 模块分工 谁负责哪个 feature/目录 ## 协作规范 分支命名、PR 流程、代码风格 ## 红线 AI 绝对不能做的事（如直接推 main） ## 阅读顺序 先读什么、再读什么的指引
